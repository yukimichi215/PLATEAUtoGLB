# PLATEAUtoGLB

住所や地名を入れると、その周りの建物（と道路）を、国土交通省の [PLATEAU（3D都市モデル）](https://www.mlit.go.jp/plateau/) から切り出して、
3D モデル（GLB・OBJ・STL）にするツールです。3D プリンタ・Blender などの編集ソフト・[PlotBlock](https://app.plotblock.net/) などで使えます。

## できること（初版）

1. 住所・地名・駅名（または「緯度, 経度」）で場所を探す
   - **シチュエーションから探す**：「都会の駅前・地方都市の駅前・田舎の駅前」や作品のジャンル（古い木造の町並み〔ホラー・時代もの向き〕・ほのぼの〔静かな住宅街〕・近未来〔高層ビル街〕）を選ぶと、向いた地域の候補（手で選んだ見本。条件ごとに3つ）が出る。
     選んで作ると、できあがりに根拠の数値（建物の密度・平均の高さ・高い建物の割合・1970 年以前に建てた割合・木造の割合・住宅の割合）を出す。
     町の雰囲気はデータにないので、PLATEAU の建物の属性での近似。候補は特定の町の評価ではなく、データ上の特徴が近い例として出す。属性が入っていない自治体では「データなし」と出す
2. 切り出す範囲と建物の細かさを選ぶ
   - **範囲の選び方**：正方形（選んだ場所が中心。一辺 50〜1000 m）か、地図の上で**四角**（押したまま動かす）・**自由な形**（点を打って囲む）で囲む。
     囲んだときは、中心が囲んだ形の中にある建物だけを入れ、道路・地面（3D プリンタ用では台座）は囲んだ形で切る。囲んだ形は一辺 1000 m の正方形に入る大きさまで、線が交差しない形だけ
   - 地図は国土地理院の地理院タイル（淡色地図）。表示のたびに地理院のサーバーから読み込むだけで、アプリには入れていない（`src/web/map-config.ts` の1か所で差し替えられる）
   - **箱型**（LOD1）：いちばん軽い。スマホ向けのおすすめ
   - **屋根の形あり**（LOD2）：屋根の形が入る。少し重い
   - **屋根の形＋付属物**（LOD2）：ベランダ・ひさし・屋上の設備なども入る。重い（データのない地域もある）
   - **窓・扉まで＋付属物**（LOD3）：窓（青）・扉（茶色）の部品と付属物も入る。とても重い。データは沼津駅前・虎ノ門など一部の建物だけ（ない建物は「屋根の形＋付属物」で代わりに作るので、それより粗くならない）
   - 選んだ細かさのデータがない建物は、粗い形（屋根の形→箱型）で代わりに作り、その数を表示する
   - 道路・地面の板を入れるかどうか
   - **高さの強調**：建物の高さだけを 1〜3 倍にする（平らな町でも立体感が出る。幅・奥行き・道路・台座の厚さは変えない）
3. 使いみちを選ぶ
   - **そのまま**：実物の大きさ（メートル）。Blender などの編集ソフト・PlotBlock 向け
     「建物を1棟ずつ別の部品にする」を選ぶと、GLB のノード・OBJ の `o` を建物ごとに分ける（名前は PLATEAU の建物 ID。名前のある建物は「名前_ID」。編集ソフトで1棟ずつ選べる。STL は分けない）。
     GLB の各建物のノードの `extras` には、データにある項目だけ入れる：`plateauId`・`buildingId`・`name`・`usage`（用途のコード）・`usageName`（用途の名前）・`yearOfConstruction`・`storeysAboveGround`・`measuredHeight`（PLATEAU の計測値 m）・`modelHeight`（このモデルでの高さ m。高さの強調のあと）・`heightScale`（強調したとき）・`cityCode`・`lodUsed`。
     PLATEAU で「分からない」を表す値（階数 9999・建てた年 0001 など）は入れない
   - **3D プリンタ用**：縮尺（1/500〜1/10000、または台座の一辺の長さ〔mm〕）と台座の厚さ（mm。0 で台座なし）を決める。
     建物は屋根の面を真下に押し出した形に作り直し、道路（厚さ 0.4 mm の板）・台座と一緒に、穴やすき間のない1つの立体にまとめる
     （付属物・窓・扉は細かすぎて印刷できないので入れない。範囲からはみ出した部分は切り落とし、台座はちょうど切り出した正方形か囲んだ形）
     印刷するとこの太さ（mm。既定 0.8、0 で外さない）より細い建物・道路は外し、外した数を表示する
4. 「3D モデルを作る」を押すと、必要な地域のデータだけを PLATEAU から取り、その場で 3D モデルにする
5. 3D のプレビューで確かめて、形式を選んで保存（マウスで回して見られる。「斜めから・真上から・正面（南）から」のボタンで向きを切り替え。床のマス目に1マスの長さが出る。3D プリンタ用は印刷したときの大きさで出る）
   - **GLB**：色付き・1ファイル（PlotBlock・Web 向け）。中に出典を書いてある
   - **OBJ**：色付き（Blender などの編集ソフト向け）。`.obj`・色の設定 `.mtl`・出典の文章を zip にまとめて保存
   - **STL**：色なし（3D プリンタ向け）。`.stl` と出典の文章を zip にまとめて保存
   - **すべてまとめて**：上の全部と出典の文章を1つの zip に
   - OBJ・STL はファイルの中に出典を書ききれないので、出典の文章ファイルと必ず一緒に出す

作られる形（GLB・OBJ・STL 共通）：

- 1つの `.glb` に全部入り（外部ファイルの参照なし）。Draco などの形の圧縮は使わない
- 単位はメートル、上は +Y、北は -Z（OBJ・STL も GLB と同じ）。切り出した範囲の中心が原点、地面が高さ 0
- 3D プリンタ用のとき：OBJ・STL はミリメートル（印刷ソフトの標準）、STL は上が +Z（北が +Y）。GLB は glTF の決まりどおりメートルで、縮尺をかけた大きさ。
  台座の上面が高さ 0。建物・道路の下端は台座の厚さの半分まで食い込ませ、台座とつなげる
- OBJ は同じ位置の頂点を1つにまとめ、部品（`o`）は GLB と同じ名前。STL はバイナリ形式で、先頭に出典が別ファイルにある旨を英字で書く
- 建物の底の面は省いて三角形を減らす。模様（テクスチャ）は使わず、壁・屋根・付属物・道路・地面の色分け
- 中身は「Buildings」「Roads」「Ground」の3つの部品（建物を1棟ずつ分けたときは、Buildings の下に建物ごとの部品）
- GLB は `asset.copyright` と `extras.plateau`、OBJ・.mtl は先頭のコメントに出典（自治体・年度・データ名・ライセンス・入手先）と「加工して作成」の旨を記録

まだできないこと：地形（坂・高低差。建物は地面の高さ 0 にそろえて並べる）、橋・木など、建物の模様・窓（PLATEAU の写真の模様は一部の地域にしかなく粗いため使わない。窓の形のデータはほぼない）。

## 使い方

### ブラウザ版

ブラウザで動くアプリです（Windows 版はやめ、ブラウザ版に一本化しました）。作ったファイルはブラウザのダウンロードで保存します。
Web での公開の方法は検討中です。それまでは、パソコンに Node.js を入れて次のように起動します。

```sh
npm ci --ignore-scripts
npm run dev
```

表示された `http://localhost:5173/` をブラウザで開きます。

一度取った PLATEAU のデータは手元（ブラウザの保存領域）に保存して使い回します（画面の一番下のリンクで消せます）。
東京の中心部などでは、1km 四方のデータが展開後 100〜200MB 程度あります（通信は圧縮されるので 1〜2 割程度）。

## データと出典

- データは PLATEAU のデータカタログ API（`api.plateauview.mlit.go.jp`）で場所に合う約1km四方のファイルを調べ、
  公式の配信元（`assets.cms.plateau.reearth.io`）から取得します。
- 住所の検索には国土地理院の住所検索（`msearch.gsi.go.jp`、無料・登録不要）を使います。
- 範囲を選ぶ地図は国土地理院の地理院タイル（淡色地図。https://maps.gsi.go.jp/development/ichiran.html ）です。地図の右下に「地理院タイル」と出典を出します。測量法の申請が要らない使い方（表示のたびに読み込むだけ）にしています。ズーム 5〜8 は追加の出典が要るので、9 以上だけを使います。
- PLATEAU のデータは「公共データ利用規約（第1.0版）」（CC BY 4.0 互換）で、出典の表示が必要です。
  作ったもの（ファイル・3D プリントした物・画像や映像）を使うときは、一緒に保存されるクレジットの文章の出典を表示してください
  （PlotBlock では素材のクレジット欄に貼る）。
  利用条件：https://www.mlit.go.jp/plateau/site-policy/

## 開発者向け

| コマンド | 内容 |
|---|---|
| `npm run dev` | 画面を開発用に起動 |
| `npm run typecheck` | 型チェック |
| `npm test` | 自動テスト（`tests/`。小さな見本データ `tests/fixtures/` を使い、glTF Validator と three.js の GLTFLoader で GLB を検査） |
| `npm run build` | 型チェックと公開用のファイル作成（`dist/`） |
| `npm run cli -- --lat 35.6812 --lon 139.7671 --size 300 --lod 1 --name 東京駅` | コマンドで GLB を作る（`--format glb,obj,stl` で OBJ・STL も。出典の文章はいつも一緒に出す）（`--lod 2 --installations` で付属物、`--lod 3` で窓・扉）（取得したデータは `data/cache/` に保存。1ファイル200MB・合計1000MBを超えると中止） |
| `npm run cli -- … --print --scale 1000 --base-mm 3`（または `--fit-mm 100`） | 3D プリンタ用（縮尺・台座・閉じた形）で作る |
| `npm run cli -- … --height-scale 1.5` | 建物の高さだけを 1.5 倍にする（1〜3） |
| `npm run cli -- --polygon "35.682,139.766;35.682,139.768;35.680,139.767" …` | 囲んだ形（緯度,経度 を ; で区切る。3点以上）で切り出す（`--lat`・`--lon`・`--size` はいらない） |
| `npm run cli -- … --separate` | 建物を1棟ずつ別の部品にする（GLB・OBJ。3D プリンタ用では使わない） |
| `npm run cli -- … --print --min-mm 0.8` | 3D プリンタ用で、印刷すると 0.8 mm より細い建物・道路を外す（0〜10。既定 0.8、0 で外さない） |
| `npm run check-situations` | シチュエーション検索の候補の地域に、PLATEAU の建物のデータがあるかとファイルの大きさを、データカタログで確かめる（データ本体は取らない。国土地理院の住所検索で名前の位置との距離も出す） |
| `npm run verify -- out/xxx.glb out/xxx.obj out/xxx.stl` | GLB を glTF Validator と three.js で、OBJ・STL を three.js の OBJLoader・STLLoader で検査し、外形・三角形の数・部品の数（GLB は Buildings・Roads・Ground ごと）を表示。STL は印刷できる形か（開いた辺・3つ以上の面が共有する辺・部品の数・体積が正か・台座から浮いた部品）も表示 |

画面の言語：右上で日本語・English を切り替えられる（最初はブラウザの言語。選んだものを覚える）。文言は `src/web/i18n/ja.ts`・`en.ts`（HTML は `data-i18n` のキーで辞書から入れる）。中身の処理の知らせ（進み具合・エラー）は日本語で作り、英語の画面では `src/web/i18n/core-messages.ts` で訳す。住所・地名の検索は日本語だけ。出典の文章は日本語の原文のあとに英訳を付ける。訳し漏れは `tests/i18n.test.ts` が見つける。

寄付（応援）ボタン：`src/web/donate-config.ts` に OFUSE と GitHub Sponsors の URL（https のみ）を書くと、題名の横（狭い画面では下）にボタンが出る。空ならボタンは出ない。ただのリンクで、外部のスクリプト・画像は読み込まない（絵はアプリに同梱の自作のもの）。

PR を出す前の検証：`npm run typecheck`、`npm test`、`npm run build` がすべて通ること。
GLB の出力を変えたときは、さらに実データで `npm run cli` と `npm run verify` を実行し、見た目に関わる変更は画面のプレビューのスクリーンショットで確かめる。

構成：

- `src/core/` … 画面とコマンドで共通の中身（場所→メッシュ番号、データカタログ、CityGML の読み取り、三角形分割、GLB 作成、OBJ・STL・zip の書き出し〔`export.ts`〕、3D プリンタ用の閉じた形〔`solid.ts`〕・縮尺と台座〔`print.ts`〕・1つの立体にまとめる計算〔`union.ts`。manifold-3d〕、出典）
- `src/web/` … ブラウザの画面。重い処理は Web Worker（`worker.ts`）で行う
- `scripts/` … コマンド（GLB 作成・検査）
- `.github/workflows/build.yml` … 自動ビルド。PR と main で検査と画面のビルドができるかを確かめるだけ（できたファイルは保存しない）

自動ビルド：PR と main で「検査（型チェック・テスト・画面のビルド）」が通ることを確かめる（できたファイルは保存しない）。
